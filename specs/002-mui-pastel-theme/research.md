# Research: Tailwindのみでパステルテーマを統一するベストプラクティス

**Feature**: [specs/002-mui-pastel-theme/spec.md](spec.md)
**Date**: 2026-02-26

## 背景（このリポジトリの現状）

- フロントは Vite + React 18。
- Tailwind CSS が導入済みで、[frontend/src/index.css](../../frontend/src/index.css) で `@tailwind base/components/utilities` を読み込んでいる。
- 既存の画面は主に [frontend/src/pages/ItemsPage.tsx](../../frontend/src/pages/ItemsPage.tsx) に集約されているが、本featureは「フロントエンドの全ページ（将来追加含む）」が対象。

## 結論（推奨アプローチ）

### 推奨: Tailwindで「意味的トークン」→ コンポーネント/要素に適用

- パステル基調を「色の寄せ集め」にせず、**用途ベース（背景/面/枠/テキスト/アクセント/エラー）**のトークンとして揃える。
- 実装は、Tailwindの既存カラーパレット（例: `slate-*`, `sky-*`, `pink-*`, `emerald-*`, `red-*` など）を中心に組み立て、ページごとの色ブレを防ぐ。

## 重要: 可読性（FR-004）の満たし方

- パステル背景はコントラスト不足が起きやすい。
- 重要テキスト（ボタンラベル/入力ラベル/エラーメッセージ等）は **WCAG AA目安**（通常文字 4.5:1、太字/大文字 3:1）を満たす前提で、
  - 文字色を濃くする（例: `text-slate-900` 系）
  - 背景を明るくし過ぎない（例: 面は `*-50`/`*-100` を上限にする等）
  - エラー色は「パステルに寄せすぎない」（高コントラスト色を許容）
 で対応する。

## 実装ガイド（Tailwind）

### 1) 共通の見た目を置く場所

- **第一候補**: [frontend/src/index.css](../../frontend/src/index.css) に `@layer components` で、共通クラス（例: `.app-card`, `.app-input`, `.app-button-primary`）を定義する。
- **第二候補**: `tailwind.config.ts` で theme extension を行う（ただし、目的は「クラス量の削減」と「一貫性」なので、拡張は最小限）。

### 2) クラス爆発を避ける

- ページ/部品ごとに `className` を積み増しすると統一が崩れやすい。
- 反復する見た目は共通クラスへ寄せ、変更点を一点に集約する。

### 3) レスポンシブ

- 画面幅対応は Tailwind のブレークポイント（`sm`, `md`, `lg`）を基本に、
  - フォームと一覧（表）が横並びにならない/はみ出さない
  - 主要操作（追加/削除）が操作不能にならない
 ことを優先して調整する。

## アンチパターン

- ページごとに別々のパステル色を選び始めて「統一」が崩れる
- エラー/警告の色までパステルに寄せすぎて判別できない
- コンポーネント化を急ぎすぎて、UXではなく抽象化が増える
