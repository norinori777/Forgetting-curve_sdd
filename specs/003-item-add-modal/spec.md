## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一覧から追加モーダルで登録できる (Priority: P1)

学習者として、一覧画面の右上のボタンから「学習項目追加モーダル」を開き、入力して追加できるようにしたい。そうすることで、一覧の閲覧と追加の導線が分離され、迷わず追加操作を行える。

**Why this priority**: 学習項目の追加は主要な入口であり、導線が分かりやすいことが最優先の価値になるため。

**Independent Test**: 一覧画面を開き、右上ボタン→追加モーダル表示→タイトル等入力→追加→一覧に反映、までが完了することで独立に検証できる。

**Acceptance Scenarios**:

1. **Given** 学習項目の一覧が表示されている, **When** 一覧の右上のボタンをクリックする, **Then** 学習項目追加モーダルが開く
2. **Given** 学習項目追加モーダルが開いている, **When** 必須項目を入力して「追加」ボタンをクリックする, **Then** 追加処理が実行され、成功した場合はモーダルが閉じ、一覧に新しい項目が表示される
3. **Given** 学習項目追加モーダルが開いている, **When** 必須項目を未入力のまま「追加」ボタンをクリックする, **Then** 入力不備が分かる表示がモーダル内に出て、モーダルは閉じない

---

### User Story 2 - キャンセルで閉じて入力を破棄できる (Priority: P2)

学習者として、入力途中で「キャンセル」を押すとモーダルを閉じ、入力内容を破棄（クリア）したい。そうすることで、誤入力や途中中断を気軽に行える。

**Why this priority**: モーダル化により「閉じる/破棄」の体験が必須となり、誤って入力が残ると混乱や誤登録に繋がるため。

**Independent Test**: モーダルを開き、何か入力してキャンセル→閉じる→再度開く→入力が空、を確認できれば独立に検証できる。

**Acceptance Scenarios**:

1. **Given** 学習項目追加モーダルが開いていて入力中である, **When** 「キャンセル」ボタンをクリックする, **Then** モーダルが閉じ、入力中の内容はクリアされる
2. **Given** 「キャンセル」によりモーダルを閉じた, **When** 再度モーダルを開く, **Then** 入力欄は初期状態（空）で表示される

---

### Edge Cases

- 追加処理の実行中に重複操作ができない（例: 「追加」ボタンが無効化される）
- 追加処理が失敗した場合、失敗が分かる表示がモーダル内に出て、ユーザーが修正または再試行できる（モーダルは閉じない）
- キャンセル操作では、入力内容が確実に破棄され、次回表示時に残らない

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 学習項目の一覧領域の右上に、学習項目追加モーダルを開くためのボタンを表示する
- **FR-002**: System MUST FR-001 のボタン押下で学習項目追加モーダルを開く
- **FR-003**: System MUST 学習項目追加モーダルの下部に「キャンセル」ボタンと「追加」ボタンを配置する
- **FR-004**: System MUST 「キャンセル」ボタン押下でモーダルを閉じ、入力中の内容をクリアする
- **FR-005**: System MUST 「追加」ボタン押下で追加処理を実行する
- **FR-006**: System MUST 追加処理が成功した場合、モーダルを閉じ、入力中の内容をクリアし、一覧に追加結果を反映する
- **FR-007**: System MUST 追加処理が失敗した場合、失敗が分かる表示をモーダル内に出し、モーダルを閉じない
- **FR-008**: System MUST 追加処理の実行中、重複送信を防止できる状態にする（例: 「追加」ボタンを無効化する）
- **FR-009**: System MUST 本機能は「追加の導線と入力UI」を変更対象とし、学習項目のデータ内容や既存の学習スケジュール算出などの挙動は変更しない
- **FR-010**: System MUST モーダルは背景クリックおよび ESC キーでも閉じられ、その場合は「キャンセル」と同じ挙動（閉じる＋入力クリア）とする

### Acceptance Criteria for Functional Requirements

- **FR-001**: 一覧領域の右上に、モーダルを開くボタンが表示される
- **FR-002**: ボタン押下でモーダルが表示され、入力が可能になる
- **FR-003**: モーダル下部に「キャンセル」「追加」が常に表示される
- **FR-004**: キャンセル押下でモーダルが閉じ、再表示時に入力欄が空である
- **FR-005**: 追加押下で追加処理が開始される（処理開始がユーザーに分かる）
- **FR-006**: 追加成功時にモーダルが閉じ、一覧に追加された項目が表示される
- **FR-007**: 追加失敗時に失敗が分かる表示がモーダル内に出て、モーダルは閉じない
- **FR-008**: 追加処理中に同一内容での連打による重複操作ができない
- **FR-009**: 追加導線以外（一覧表示/削除/復習予定等）の挙動が変わらない
- **FR-010**: 背景クリックまたは ESC キーでモーダルが閉じ、再表示時に入力欄が空である

### Assumptions

- 一覧右上のボタンは「学習項目追加モーダルを開く」用途であり、文言は「新規」とする
- モーダルのクローズ手段は「キャンセル」「追加成功」に加え、「背景クリック」「ESC」も利用できる（背景クリック/ESCはキャンセルと同じ扱い）

### Dependencies

- 学習項目の追加処理が既存のバックエンド機能として利用可能であること

### Key Entities *(include if feature involves data)*

- **学習項目**: 学習する単位。主な属性はタイトル（必須）、内容（任意）、タグ（任意）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初見ユーザーが、一覧画面から学習項目追加モーダルを開き、1件追加して一覧に反映されるまでを60秒以内に完了できる
- **SC-002**: 「キャンセル」で閉じた後に再度モーダルを開いた場合、入力欄が空であることが常に再現できる（10回連続で再現）
- **SC-003**: 入力不備または追加失敗時に、ユーザーが失敗を認識し、同じ画面で修正または再試行できる（ユーザーテストでタスク完了率90%以上）
