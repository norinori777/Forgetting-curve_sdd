## User Scenarios & Testing *(mandatory)*

### User Story 1 - 左端のアプリタイトルで迷わない (Priority: P1)

ユーザーは、どの画面でもヘッダー左端に表示される「アプリタイトル（+アイコン）」を見ることで、利用中のアプリ文脈を即座に把握できる。

**Why this priority**: 画面遷移後も文脈が維持され、操作の迷いが減る。

**Independent Test**: 任意の画面を開き、ヘッダーの左端にアプリタイトル（+アイコン）が常に表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** ユーザーがアプリ内の任意の画面を表示している, **When** 画面が描画される, **Then** ヘッダー左端にアプリタイトル（+アイコン）が表示されている
2. **Given** ユーザーが複数の画面を行き来した, **When** 画面を切り替える, **Then** 常にヘッダー左端にアプリタイトル（+アイコン）が表示され続ける
3. **Given** アプリタイトルが長い, **When** ヘッダーが表示される, **Then** アプリタイトルの表示は完全に欠落せず、必要に応じて省略表示される
4. **Given** アイコンが表示できない（読み込み失敗等）, **When** ヘッダーが表示される, **Then** アプリタイトルは表示され、メニュー操作も可能である
5. **Given** ユーザーがヘッダー左端のアプリタイトル（+アイコン）をクリックする, **When** クリックする, **Then** 画面遷移は発生しない

---

### User Story 2 - ヘッダーメニューを参照画像どおりに利用できる (Priority: P2)

ユーザーは、参照画像に沿った配置・見た目のヘッダーメニューを利用し、「復習」「集計」「設定（プリセット）」へ迷わず移動できる。

補足: ブランド表示（アイコン+アプリタイトル）は左端に集約し、右端にはブランド要素を表示しない（Clarifications参照）。

**Why this priority**: 既存の主要導線を維持しながら、見た目の指針（画像）に基づく一貫性を確保できる。

**Independent Test**: 参照画像と見比べ、(1) メニュー3項目が表示される、(2) クリックで対応画面に移動できる、(3) 現在ページがアクティブ表示で判別できる、を確認する。

**Acceptance Scenarios**:

1. **Given** ユーザーが任意の画面を表示している, **When** ヘッダーの「復習」を選択する, **Then** 復習画面が表示され、ヘッダーの「復習」がアクティブ表示になる
2. **Given** ユーザーが任意の画面を表示している, **When** ヘッダーの「集計」を選択する, **Then** 集計画面が表示され、ヘッダーの「集計」がアクティブ表示になる
3. **Given** ユーザーが任意の画面を表示している, **When** ヘッダーの「設定（プリセット）」を選択する, **Then** 設定（プリセット）画面が表示され、ヘッダーの「設定（プリセット）」がアクティブ表示になる

---

### User Story 3 - 画面幅が変わってもヘッダーが崩れない (Priority: P3)

ユーザーは、画面幅が狭い場合でもメニューが欠落せず、参照画像の意図どおりに読み取れる。

**Why this priority**: モバイル相当の利用でも、主要導線が保たれる。

**Independent Test**: 画面幅を狭くして、(1) 3メニューが常に操作可能、(2) レイアウトが2段になり、(3) 左端のタイトルが維持される、を確認する。

補足（試験条件の例）: 表示幅の代表例として、幅 1280px 程度（デスクトップ相当）と幅 375px 程度（スマートフォン相当）で確認する。

**Acceptance Scenarios**:

1. **Given** 画面幅が狭い状態で主要ページを表示している, **When** ヘッダーが表示される, **Then** メニュー3項目は常に表示され、操作可能である
2. **Given** 画面幅が狭い状態で主要ページを表示している, **When** ヘッダーが表示される, **Then** ヘッダーは2段に折り返して表示される（詳細は要件に従う）
3. **Given** 画面幅が狭い状態で主要ページを表示している, **When** ヘッダーが表示される, **Then** 1段目に左端の「アイコン+アプリタイトル」、2段目にメニュー3項目が表示される

### Edge Cases

- アプリタイトルが長い場合でも、タイトル表示が完全に欠落しないこと（省略表示は許容する）
- 画面幅が狭い場合でも、3メニュー項目が欠落せず常に操作可能であること
- アイコンが表示できない場合でも、アプリタイトルとメニュー操作が維持されること
- 現在ページのアクティブ表示が、狭い画面でも判別できること

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはアプリ内の全画面（全ルート）でヘッダーを表示しなければならない
- **FR-002**: ヘッダー左端には、アイコンとアプリタイトルを表示しなければならない
- **FR-003**: ヘッダーには、メニューとして「復習」「集計」「設定（プリセット）」の3項目を表示しなければならない
- **FR-004**: メニュー表示順は左から「復習 → 集計 → 設定（プリセット）」でなければならない
- **FR-005**: ユーザーは各メニュー項目を1回の操作で対応画面へ遷移できなければならない
- **FR-006**: 現在表示中ページに対応するメニュー項目は、他項目と区別できるアクティブ表示でなければならない
- **FR-007**: 幅 1280px 程度の表示条件では、メニュー3項目は横並びかつ等間隔に配置されなければならない
- **FR-008**: 幅 375px 程度の表示条件では、ヘッダーは2段に折り返して表示されなければならない
- **FR-009**: 幅 375px 程度の表示条件でも、3メニュー項目は常に表示され、操作可能でなければならない
- **FR-010**: アイコンが表示できない場合でも、アプリタイトルとメニューの表示・操作は維持されなければならない
- **FR-011**: 仕様書は、ヘッダーデザインの参照画像を含まなければならない
- **FR-012**: ヘッダー右端には、ブランド要素（アイコン/アプリタイトル）を表示してはならない（左端に集約する）
- **FR-013**: ヘッダー左端のアプリタイトル（+アイコン）は、クリック（タップ）しても画面遷移しない（表示のみ）
- **FR-014**: 幅 375px 程度の表示条件で2段表示になる場合、1段目には左端の「アイコン+アプリタイトル」を表示し、2段目にはメニュー3項目を表示しなければならない
- **FR-015**: ヘッダー左端に表示するアプリタイトル文字列は "Forgetting-curve" でなければならない
- **FR-016**: ヘッダー左端のアイコンは、テキストのモノグラム "FC" で表示しなければならない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 主要ページでヘッダー左端に「アイコン + アプリタイトル」が表示される状態を、表示試験で100%確認できる
- **SC-002**: ユーザーは任意の主要ページから、ヘッダーメニューの1回の操作で「復習」「集計」「設定（プリセット）」のいずれにも到達できる
- **SC-003**: 幅 375px 程度の表示条件でも、3メニュー項目が常に表示・操作可能であることを表示試験で100%確認できる
- **SC-004**: 参照画像（spec内添付）と実画面のヘッダーが、レビューで「意図どおり」と判定される（レビュー参加者2名以上の合意で記録できる）

## Assumptions

- アプリタイトルの表示文字列は "Forgetting-curve" とする（Clarifications参照）
- アイコンはテキストのモノグラム "FC" とする（Clarifications参照）
- 「設定」はプリセット管理画面を指し、表示ラベルは「設定（プリセット）」とする
- 参照画像は、この仕様書に添付された画像を「完成形の判断基準」として用いる
